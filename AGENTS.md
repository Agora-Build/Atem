# AGENTS.md

This file provides guidance to AI coding agents working with this repository.

## Project Overview

Atem is a terminal that connects builders, Agora platform, and AI agents. It provides a CLI and TUI for managing Agora projects and tokens, routing tasks between Astation and AI coding agents, and more.

Install:

```bash
# Quick install (works in regions where GitHub is not available)
curl -fsSL https://dl.agora.build/atem/install.sh | bash

# Or via npm
npm install -g @agora-build/atem
```

### Core Components

**TUI State Machine** (`app.rs`): bare `atem` is a menu and a client of `atem runtime`; it opens no Astation connection (the runtime owns the machine's one link). Enum-based mode switching via `AppMode`:
- `MainMenu` - Navigation between features
- `TokenGeneration` - Token creation UI
- `CommandExecution` - Shell command runner
- `AgentPanel` - The runtime's sessions (Enter attaches); agent sessions open in `tui/frontend.rs`

**Mark Task Queue** (`app.rs`, `dispatch.rs`, `command.rs`; inside `atem runtime`): Receives task assignments from Astation, reads task JSON from the local `.chisel/tasks/` directory of the live broker Claude session whose working directory holds it (none: `markTaskResult` fails with "no Claude session for this project; run `atem agent launch claude` there"), builds prompts from annotations + screenshots, writes them to that session through its worker as local-origin input (no lease is revoked; a task waits while a remote lease holder exists), reports results back.

Key pieces:
- `App.dispatcher: TaskDispatcher` - routes each `WorkItem` to its project's broker Claude session (serial `TaskQueue`: FIFO, one active, deferred-finalize flag) or, when main is busy and a slot is free (max 2), to a background `claude -p` if a one-turn triage call (`claude -p --model haiku`) picks background (`CLAUDE_CLI_BIN` overrides the binary)
- `App.work_items: HashMap<String, WorkItem>` - built items by task ID

Key methods:
- `load_and_build_work_item()` - reads the task JSON, builds the prompt (`build_mark_task_prompt()`)
- `try_dispatch_main()` - when main is idle and the target session has no remote lease holder, pops the next task and queues its prompt for the broker (`Hosted::writes`)
- `finalize_mark_task()` - reports the main task's result to Astation, dispatches the next
- The runtime's pass drains triage verdicts and background results and runs `finalize_mark_task()` when the deferred-finalize flag is set

**Astation Integration** (`websocket_client.rs`): WebSocket protocol with `AstationMessage` enum:
- `MarkTaskAssignment { task_id, received_at_ms }` - received from Astation
- `MarkTaskResult { task_id, success, message }` - sent back to Astation
- `SessionWire(String)` - every inbound `session`, `terminal` and `agentChat` message, as raw JSON for the session host's strict decoder (`session_family` peeks the `type`); outbound host messages are written as is (`try_send_wire`; terminal-v1 on the bounded terminal queue, in order with the frames). `SessionOversize { id }` - one larger than 32 KiB (terminal) or 1 MiB (session, agentChat), dropped unread and answered with a session `error` `unsupported_version`

**Runtime** (`src/runtime/`, `designs/agent-runtime.md`): `atem runtime` (bare: the runtime process itself, started by the commands that need it; one per config dir: an exclusive `flock` on `<config>/runtime.lock` holding its pid, the socket `$XDG_RUNTIME_DIR/atem/runtime.sock` (else in the config dir) recorded in `<config>/runtime.socket`, output in `<config>/runtime.log`) is the broker: it serves local frontends over the same-user socket (local protocol v1, `runtime/protocol.rs`: `hello`, `launch`, `attach`, `detach`, `input`, `paste`, `resize`, `reclaim`, `list`, `stop`, `reload`, `status`, `restart`, `astation_op`/`answer` in; `welcome` (with `worker_protocol`), `launched`, `attached`, `output`, `exited`, `sessions`, `detached`, `stopped`, `session`, `astation`, `status`, `restarting`, `notice`, `print`/`ask`/`done`, `error` out), holds the App with the machine's one Astation link, and owns the session host. Clients (`atem agent …`, bare `atem`, `atem pair`/`pair verify`/`cred unlock|projects`) start it detached when none answers; a runtime of another protocol without live sessions restarts for them. A non-passive client of another build replaces it by its own (`client::replace_other_build`, whose doc comment has the rules): `restart` → `restarting`, the runtime exits after that pass (a runtime that doesn't know `restart` gets SIGTERM, only when `runtime.lock` names its pid and that pid is confirmed as this user's `atem runtime`), the client starts its build, which adopts the workers, and prints `Atem's runtime updated to <build> (was <build>); sessions kept.`; it is kept, with a message saying why, when its `welcome.worker_protocol` differs (naming the sessions that block it), while it is busy (an Astation operation runs or a session is starting: `restart` is refused), or within 60 s of the last replacement (`runtime.replaced`, against two builds flapping). `atem runtime restart` does the same on request (no 60 s guard). Once `restart` is accepted, the exiting runtime refuses new work (`launch`, `attach`, `astation_op`, `restart`: `RESTARTING_NOW`; a new `hello`: `RESTARTING`, so the client waits for the next runtime), and its other frontends get `restarting` and reattach on their own (`RuntimeClient::reconnect`, a brief notice, then a fresh restore of the same session). If another client already replaced it, a second replacer finds the new runtime (another pid in `runtime.lock` or on the socket) and joins it. `status` (passive, read-only) returns the link (`transport`, relay label, retrying), the attachment (welcomed revision, time, authorization left; the last refused `hello` revision), whether the journal halted, and the sessions (with each worker's `build` from its `hello`); `atem status` and `atem --version` read it within 500 ms (`client::look`, a blocking passive client that never starts or keeps a runtime). It exits after 10 minutes with no sessions and no non-passive clients (`ATEM_RUNTIME_IDLE_SECS` overrides), on SIGTERM/SIGINT, or when replaced. Every session runs in its own `atem worker --state <config>/runtime --session <id>` (hidden, spawned detached; socket `$XDG_RUNTIME_DIR/atem/workers/<id>.sock`, else `<config>/runtime/workers/`; spec, record (`session_id`, `process_gen`, pids and OS start times, exit) and log in `<config>/runtime/workers/`), which owns the agent's PTY, the canonical screen, Claude's chat adapter and the session log, and outlives the broker: a new broker adopts each surviving worker only when its `hello` names the record's session id and process generation and the pid's OS start time matches (Linux `/proc/<pid>/stat` field 22, macOS `proc_pidinfo`); otherwise the session is `recovery_required` (or `interrupted`/`exited`) and nothing is restarted or replayed. The broker is the only writer authority: every write and paste carries the input epoch it granted, and the worker drops one whose epoch is older than its current one at the PTY write boundary (`pty_session.rs` fenced writes). Session ids are `ses-` + 12 base32 characters; each process is a new `process_gen` (UUID).

**Session host** (`runtime/host_bridge.rs`, `session_protocol/`, `app/hosted.rs`; contract `designs/protocol/atem-session-v1.md` r8, its appendix authoritative, compatibility mode): only `atem runtime` serves sessions remotely. Its broker owns `SessionHost` over a `FileJournal` in `<config>/runtime/journal/` (per-session receipt logs under `receipts/`, 0700/0600, `O_NOFOLLOW`, fsync per transition, compaction, a lease-epoch floors file, `principals` (each principal's `control` and `control_gen`), `refused` (the refusal list), `clean_close`, `journal.lock`, and a `runtime_epoch` counter incremented at each start) and makes the App's authenticated Astation link one attachment — new on every connect or re-authentication (`App::astation_link_gen`), fenced when the link drops or is re-authenticated, so clients `hello` again and an old `attachment_gen` is `stale_target`. Revision admission (r8 §A, `session_protocol/revision.rs`): a `hello` must carry `revision: 8`; without it (or with another number) it gets session `error{code:"unsupported_version", revision: 8}` and nothing else (no attachment; later requests are refused as before `welcome`); `welcome` echoes `revision: 8` and lists `features`, all nine (`chat.history_end`, `chat.history`, `chat.lookup`, `chat.coverage`, `receipt.result`, `approval.session_rules`, `approval.card_reason`, `chat.send_acquire`, `approval.lease_free`); the forms r8 removed (`open.before`/`open.generation`, `acquire` on an approval answer) are `unsupported_version` with no effect, and a field-rule violation is `invalid_request`. A second `hello` on the same authenticated link (Astation reset its client, e.g. after sleep) replaces the attachment (`Effect::Replaced`): the old one is fenced (its leases end, streams and conversations close), the new one gets a new `attachment_gen`/`controller_session` with the link's unchanged authorization deadline; receipts stay; at most one a second (`busy`). runtime.log gets one `HH:MM:SS` UTC line per `hello` (welcome, replaced, refused `<code>`), and one per other refused request (`runtime/refusal_log.rs`: `refused <family>/<op>[ kind=<kind>] <code>[ session=<sid>][ (<reason>)]`, oversize and full-inbox drops included; decode failures keep only the serde category and field name, never content; at most 20 lines per 10 s per link, then "… N more refusals suppressed"). Only the paired Astation the link captured, verified in `cred/state.json`, gets one (`view`, `control`, `client_kind` `native`); any other link gets none and its session messages are answered `unauthorized`. `welcome` names the verified `data_account` (`account_id`), this device's verified `device_id` (`atem_device_id`) and the `host_trust_gen` of `pairing/trust_gen`; `runtime_gen`/`runtime_epoch` change when the broker restarts or the identity changes (a pairing verified after the broker started rebinds the host over the same journal). The attachment is authorized for 24 h (no freshness proof yet), on the monotonic clock and in wall time, whichever ends first: then it is fenced and the link dropped, and the reconnect authenticates again (an r9 host, which refuses r8, never welcomes that attachment and keeps its link past the 24 h; each r9 channel has its own lifetime, see r9 below). Every 5 s the broker re-checks the link's pairing capture against the pairing and drops a link whose pairing changed (unpair works even without `reload`). Session-v1 (`hello`, `list` → `sessions`/`session_changed` with a per-attachment `seq`, `acquire`/`renew`/`release` → 15 s leases with explicit `takeover`, `submit` → receipts, `receipt_query`) is the registry and the only way to get control; `lease_held` names the holder (`controller{controller_session, lease_epoch}`, text "another controller holds this session"). Chat Send (r8 §F): a `prompt` submit (session-v1, or chat-v1 `text`) may carry `acquire: true` (no `lease_epoch`), with `takeover: true` plus `expected_controller` for a confirmed takeover: nobody holding → the prompt's durable acceptance and the grant are one step; the sender holding → its lease, unchanged; another holding → `lease_held` (a stale `expected_controller` too); the admitting reply carries `lease{lease_epoch, ms_left}`; only prompts acquire (`interrupt`/`stop`/rule revoke with `acquire` are `invalid_request`), and the flags are admission parameters outside the digest (a duplicate returns its receipt and never acquires). Principals and the control fence (r8 §H): each attachment speaks for the principal its link authenticated (today `astation:<account>:<astation id>`, `link_principal`); accepted work records the submitter principal and its `control_gen`; a link that re-authenticates without `control` writes the fence (`principals`) first, then fences that principal's attachments, revokes its lease and rejects its queued work (`control revoked`); a dispatch checks the principal still holds `control` at that generation. Persistence (r8 §I): a request is accepted only once its `accepted` record is durable; any failed journal write halts the journal until a restart (every session request but `hello` is `busy` "journal halted; restart Atem", a new link's `hello` gets no `welcome` and no reply while its other requests are `busy`, nothing queued is dispatched and no remote byte passes `admit_write`); a failed admission write goes on the refusal list first and is answered `busy` "acceptance not recorded" (if even that fails, the link is closed without a reply). An orderly stop (SIGTERM/SIGINT, idle exit, replacement) with a healthy journal writes `clean_close` (`{"runtime_epoch": n}`; runtime.log "session journal closed cleanly"). At start, recovered queued work is resolved in order: on the refusal list → `rejected` "acceptance not confirmed"; no clean close, or a queued request whose principal `principals` doesn't name at its `control_gen` (the file lost or older) → "authorization history unknown"; trust changed → "host trust changed"; an older `control_gen` → "control revoked"; else it waits for its principal to be welcomed with `control` and is "control not confirmed" 60 s after the start. Receipts per kind: `prompt` is pasted once `ChatSession::submit` accepts it and completes at the chat's turn end with `detail` `done` or `interrupted`, its completed receipt carrying `result{turn_id, user_message_id, outcome, reply_message_ids, more, replies}` (r8 §D: the two ids are journaled with the transition, never text; the reply ids — the turn's assistant messages in timeline order, approval cards left out, at most 32, `more` when more are retained — and `replies` (`complete`/`partial`/`unavailable`, `partial` when the user message was evicted, a hole touches the turn or an id can't be named and is dropped) are filled from the broker session's retained history each time the receipt is sent; the user message id is recorded per request when the prompt is accepted, so it is known after eviction; only a turn or user message id that isn't an opaque id journals no result) (a session without chat — Codex with `[codex] hooks` off, Claude before its SessionStart or after its chat was withdrawn — rejects it with no effect: "chat is not available for this agent; use the terminal"); `interrupt` writes Esc only while the chat status is `working` or `waiting` and completes when that turn ends, completes at once with nothing written in `ready` or `unknown`, and is `rejected` ("no turn state; use the terminal") whenever the session has no turn state, for any agent (Codex with its hooks off, Claude before its SessionStart or after its chat was withdrawn), never a blind Esc; `stop` completes at the exit; `approval` completes when the agent applied the decision (see Approval hooks). A refused-before-queueing write is `rejected`, a writer error after queueing `outcome_unknown`; executing work is `outcome_unknown` after a broker restart (never retried); duplicate submits return the recorded receipt, the same `request_id` with other content is `request_id_reused`. Terminal-v1 (`subscribe`/`unsubscribe`/`ack`, and `input`/`resize`/`stop` with the lease; terminal id = session id) and chat-v1 (`open`/`history`/`submit` with a binding, `close` with or without one, a `text` `submit` with the lease or `acquire`; `accepted`/`complete`/`error{code}` from its receipt; at most 8 conversations per session) are bound families. Effects reach the workers: remote bytes are checked with `admit_write` before they are sent and tagged with the worker's input epoch, which the broker raises (`set_input_epoch`, at least the lease epoch) whenever the host's epoch moves after remote bytes or while a lease was held; remote writes and pastes also carry `not_after`, the lease's deadline on CLOCK_MONOTONIC (`pty_session::monotonic_ns`), and the worker drops one at the PTY write boundary once it has passed (reported like an epoch drop; local writes carry none); each remote `input` gets a `written` ack (`control changed; not written` when dropped, `the approval was handed to the terminal; not written` when it released a Codex approval hook); a slow terminal transport drops frames and ends streams with `busy`. Local frontend input goes through `local_input` (it revokes any remote lease first). Duplicate session messages (same attachment, `id` and content) within 60 s are handled once (at most 4096 remembered). `advance` runs every 100 ms of the session clock. Adopted workers send a `chat_snapshot` before any `chat` (the whole retained history, 500 messages / 8 MiB, older messages first in `chat_history_part` lines of ≤ 1 MiB; approval cards included, since the broker copies each card to its worker with `chat_card`; a card still pending becomes `closed`), so chat goes on after a broker restart. A `chat` with `gap > 0` makes the broker reload the worker's history (`request_chat_history` → `chat_history`, r8 §C): every new or changed message goes to open conversations as a sequenced `message{history:true, after_message_id}` (`null` without a retained predecessor; cards only where cards are shown), with no `error`, `close` or reopen; the reload also carries the worker's chat state (`ChatSession::catch_up`: a missed turn end completes its receipt) and its truncation and cut turn; a reload lost with its worker, over 1000 messages, or with no worker to ask leaves a hole (no `count`) and a sequenced `coverage` event (the session's holes, ≤ 16). History pages are served by `chat::history` (see Agent chat). Bare `atem` opens no Astation connection, so only the runtime ever sees session-family messages. A runtime whose session host could not start (its journal or a damaged `runtime_epoch`, never reset silently) answers them `unsupported_version`, and `welcome.host_error` (shown by `atem agent list` and in `runtime.log`) says why, e.g. "remote sessions disabled: <path> is damaged; move it aside to reset the runtime epoch". §9 features (resume, browser grants, account-wide access, relay confidentiality) are refused on r8; r9 (below) brings native members, services and browser grants over an end-to-end channel. A socket alive is not an authenticated Astation: when Astation sends `auth_required` over an already-authenticated socket (e.g. it alone reconnected to the relay), `app/reauth.rs` shows `Astation ✗`, fences the attachment and ignores every other Astation request, then answers only the pinned Astation non-interactively (`AstationClient::answer_auth_required`) with the connect path's proof (`local_proof` on loopback, else the saved session); success restores online as a new attachment, while denial, expiry, a different `astation_id` or no answer within 15 s leaves a notice and closes the socket for the normal reconnect (never pairing). The shared fixtures run against the real runtime in `tests/runtime_fixtures_binary.rs` (results: `designs/protocol/atem-host-handoff.md`).

Lifetimes: a native channel 24 h on the monotonic clock only (key rotation; removal fences at once), services and browsers at their expiry (wall and monotonic). Several devices at once (§R9.10): one attachment per channel, leases and takeovers as r8. **Host route proof** (§R9.7b, `atem_client::host_route`, `r9/route.rs`): the relay challenges every host connection (`host_challenge{nonce, room}`); the runtime's relay identity link answers in its reader, before Astation authenticates, with `host_route{proof}` signed by `host_channel_key` at the list's head (only a pinned list that can serve, once per challenge), and the relay verifies it with `verify_host_route` against its own log (no fallback). **Agent chat** (`src/chat/`, `runtime/worker_chat.rs`): chat-v1 lets Astation show a launched agent as a chat. Claude Code and Codex have adapters. Before each Claude spawn the worker (`chat::claude::prepare_chat`) creates `chat-<uuid>/` (0700) under `$XDG_RUNTIME_DIR/atem` (else `~/.config/atem/run`) with `settings.json` (hooks for SessionStart, UserPromptSubmit, Pre/PostToolUse, Notification, Stop, each writing its stdin JSON to its own file in `events/`) and puts `--settings <file>` and, unless resuming, `--session-id <uuid>` before the user's arguments for that spawn only; each spawn is a new generation (UUID). It also writes a `pid` file (the worker's); `atem runtime` sweeps `chat-*` directories whose pid is dead (or, without one, older than an hour) when it starts. If preparing fails, Claude starts without chat. The worker reads the event files (lifecycle only) and the transcript JSONL named by SessionStart (all message content), feeds `ChatSession` (log items before a tick's `Stop`, so `complete` follows the content), times out unaccepted prompts (10 s, never resent), re-sends status to each conversation 15 s after it last got it, and sends the results to each open conversation with its own sequence (at most 8 per agent: a ninth closes the oldest with `close{reason:"evicted"}`). A SessionStart whose transcript isn't `<session_id>.jsonl` is ignored with a notice; compaction or a resume on the same transcript keeps the turn, while startup, `/clear` or another transcript resets to ready (the old transcript is read to its end first, one tick later). Resuming another session reads its existing content as history only (no `message`/`complete`) and sends open conversations `error` "the conversation was switched; reopen the chat" and `close{reason:"switched"}`. A user entry starting with `[Request interrupted by user` ends the turn as interrupted (Esc, or deny at a permission prompt). Status: ready/working/waiting/unknown (the session-v1 descriptor's `activity`, and `STATUS` in `atem agent list`). No SessionStart within 15 s leaves chat unavailable with a notice (a late one still enables it); a transcript format change withdraws chat (open conversations get `error` and `close{reason:"withdrawn"}`); the terminal is unaffected either way. Remote chat-v1 is served by `atem runtime`'s session host: `open`, `history` and `submit` carry a session-v1 binding (`close` may omit it and then closes only the sender attachment's own conversation), a `text` `submit` the lease or `acquire: true` (r8 §F; its `accepted` then carries `lease`, and `lease_held` carries `controller`), and its `accepted`/`complete`/`error{code}` follow its receipt (`ChatSession::submit` applies: current generation, new `requestId`, clean prompt ≤ 32 768 bytes not starting with `/` or `!`, status ready, no draft; accepted when both the UserPromptSubmit hook and the transcript's user entry arrive). Prompts typed in the terminal appear as `origin: local` messages. Approval cards (see Approval hooks) appear as assistant messages `approval-<approval_id>` with one `approval` part, re-sent whole when their state changes (final ones carry `reason`, the `approval_closed` reason, r8 `approval.card_reason`), only in conversations of attachments with `control`; a chat `submit` carrying `approval` instead of `text` answers one (no lease, r8 §G). Outgoing text goes through the credential redactor. Conversations are handled only while `astation_connected` (not during re-authentication) and close on disconnect or re-authentication; a new `open` replies `opened` (status), the newest page as `message{history:true}` and a sequenced `history_end` (r8 §B, `chat/history.rs`, shared with the fixtures' fake runtime): every page is built in one step from the retained history with consecutive sequences of its conversation; `history{generation, page_id, before|turn_id|request_id|next}` pages older messages (backwards) or a turn (forwards, frozen at the first page's snapshot); pages hold ≤ 50 messages, ≤ 256 KiB of content (`ChatMessage::bytes`: ids, text, 64 bytes per part, 1 KiB per card; ≤ 2048 parts per message) and ≤ 1 MiB serialized with the `history_end` (`page{selector, count, content_bytes, wire_bytes, end, next?, coverage, oldest_retained, truncated, holes, holes_more?}`); `next` is base64url of a payload plus an HMAC-SHA256 tag under a per-run random key (`HistoryKey`), bound to attachment, conversation, session, process generation, selector, position and the reload count (else `stale_target` with `page_id`); a `before` not retained is `stale_target`; a lookup with nothing retained is an empty `unavailable` page; field errors are `invalid_request` (sequenced, with the valid `page_id`); more than 8 valid requests a second per conversation is `busy`; cards are left out for view-only attachments before the bounds, their holes and `oldest_retained` name only visible messages, a hole before everything they see is reported as `truncated: true`, and a `before` naming a card is `stale_target`; `coverage` is `partial` when the selection was evicted in part or a hole touches it; `open.before` is refused `unsupported_version`; an `open` on a running session without chat-v1 is answered `error{code:"busy"}` "chat is not available for this agent[: reason]". a message that gains a part is sent again whole (same `messageId`, every part so far; r8 sends no `delta`), never a token stream; `complete.outcome` is `interrupted` for a turn that ended interrupted, else `done` (also for a duplicate `submit` after a broker restart). Claude exiting reports `unknown` and `error`, drops the adapter (removing its directory) and keeps history readable (500 messages / 8 MiB); a respawn sends the old conversations `error` "the agent was restarted; reopen the chat" and `close{reason:"restarted"}`. Codex's chat is below. See `designs/agent-chat-host.md`.

**Codex chat** (`chat/codex/adapter.rs`, `rollout.rs`; only with `[codex] hooks = true`, else Codex has no chat and its activity is `unknown`): the worker calls `chat::codex::adapter::prepare_chat` (a `chat-<uuid>/` dir like Claude's, no extra arguments; the adapter's `Drop` removes it) and sends `hello.chat` (required: an older worker is `recovery_required`; the descriptor offers `chat-v1` for Claude or a worker that says so). Atem's hooks write `events/ev-<seq>-<Event>.json` (first line the hook's `$$ $PPID`, then its stdin; `EventReader` takes only that name, in (seq, name) order, at most 256 per poll, `O_NOFOLLOW`, ≤ 1 MiB, deleting each once read) and the rollout JSONL named by the hook's `transcript_path` (must be `<CODEX_HOME>/sessions/…/rollout-*-<session_id>.jsonl`, symlinks resolved, read with `O_NOFOLLOW`, ≤ 8 MiB per poll) carries all content: `RolloutReader` turns `event_msg` records into log items (`task_started` → turn start; `item_completed` user message, agent message, command execution → a `Bash` tool part; `task_complete` → done, `turn_aborted` → interrupted; everything else, e.g. reasoning, is skipped; a known record missing a required field withdraws chat, an automatic compaction's nested `task_started` is suppressed). Hooks pin the session: a hook counts only when the session's agent started it (`approvals::HookAgent`/`started_by`, shared with approvals: direct or through one shell it may pin or re-pin on `/new`, through a non-shell child (npm's wrapper) only the pinned session's or the first, which makes that child the agent so the real binary's `/new` re-pins and a nested `codex` can't; a wrapped hook read after its parent exited counts as foreign, harmless); a SessionStart of another session re-pins after one poll (old rollout read to its end first), or after the current turn ends (deferred). Status: `unknown` until the first hook (Codex fires SessionStart lazily, at the first prompt) with the detail "type a first prompt in the terminal: …", then `working` (UserPromptSubmit or `task_started`), `waiting` while the worker's open-approval set for this session is non-empty (its only source for remote waits) or while an approval the worker released ("no decision": input to Codex, no broker, an adopting broker that doesn't know it) sits in Codex's own dialog — until its PostToolUse or Interrupt hook, a Stop, a turn end or the turn's next rollout item (`set_approvals`), `ready` at the turn's end. A resumed rollout is read to its end at the switch (several 8 MiB reads if needed), so all of it is history. The agent's own UserPromptSubmit of another session read before that session's SessionStart (async hooks publish in either order after `/new`) re-pins like a first hook (its late SessionStart is then no restart); a nested `codex` never does. With `[codex] hooks = true` the worker itself runs the idempotent hooks.json merge (backup, read-back, restore) in the launch's `CODEX_HOME` before spawning, so sessions launched from the bare `atem` menu get every hook too; it never asks and never writes when the setting is unset or false; a failure is a session notice and Codex starts anyway. Before the first prompt chat opens but a `submit` is refused with that text (`Refused` receipt detail and chat-v1 `error.text`), since text typed into Codex's startup dialogs could answer them. A remote prompt is accepted only when UserPromptSubmit and the rollout's user message agree on `turn_id` (whitespace-blind text match), and only evidence stamped after the paste counts (`at_ms`: the event file's mtime or the log's timestamp; a whole-second time counts to the end of its second), so a local prompt typed just before is a local turn; this applies to Claude too. A turn end or prompt answers a permission request only when it is newer than the request (`opened_ms <= at_ms`); tool-result evidence keeps 1 s slack. A turn that is not the prompted one (compaction) emits no `complete`. `interrupt` writes Esc only while `working` or `waiting` and completes at the turn's end; in `ready`/`unknown` it completes at once with nothing written (Esc on a startup dialog quits Codex); with no turn state (hooks off; for Claude too: before its SessionStart or after its chat was withdrawn) it is `rejected` "no turn state; use the terminal", and a prompt "chat is not available for this agent; use the terminal". Capabilities say what Codex's chat can't do: `unavailable` = `streaming` (replies arrive whole), `reasoning`, `error_details` (Claude: `streaming`, `reasoning`; "always allow" is offered as an Atem session rule, see Approval hooks), in the worker's `chat`/`chat_snapshot` messages and chat-v1 `opened.unavailable`. Known limits: whole-second filesystems and logs allow same-second races. See `designs/agent-chat-host.md` (Codex) and `designs/fixtures/codex-hooks/README.md`.

**Approval hooks** (`src/chat/approval_hook.sh`, `chat/approvals.rs`, `chat/codex/`, `runtime/worker_approvals.rs`, `runtime/host_bridge.rs`, `runtime/push_queue.rs`; contract §6a and r8 §G): agent permission prompts reach the worker through a `PermissionRequest` hook that writes `req-<id>.json` into the session's `approvals/` dir and waits for `dec-<id>.json` (claimed by renaming it to `taken-<id>.json`, then set aside as `claimed-<id>` once read, the claim time kept; the worker withdraws an unclaimed one the same way, so exactly one side gets it, and removes the files only once the hook process is gone). Claude gets it per launch in its `--settings` (600 s; its own dialog stays visible, first answer wins) unless `[claude] approvals_hook = false` in config.toml (default on, never asked; read when the worker starts: off leaves out the `PermissionRequest` hook and its `PostToolUse` note, the chat hooks stay); Codex gets one Atem-marked entry per hook event (`chat::codex::EVENTS`: SessionStart, SessionEnd, UserPromptSubmit, PreToolUse, PermissionRequest, PostToolUse, PreCompact, PostCompact, Stop, Interrupt; commands start with `: atem-approval-hook;`, all run the one script `~/.config/atem/hooks/approval-hook.sh`, the same command for every session, `ATEM_APPROVAL_DIR` set by the worker; outside Atem they exit at once) in `$CODEX_HOME/hooks.json`, appended after the user's entries (Codex trusts each handler by position plus hash, so theirs keep their trust; the PermissionRequest entry is byte for byte the earlier one: sync, 300 s), after `atem agent launch codex` asks once (`[codex] hooks` in config.toml, one answer for approvals and chat; until it is `true` a Codex worker writes no hook script and watches nothing). The other events are `async: true` (SessionEnd is always sync), 3 s, and only record their stdin as `events/ev-<seq>-<Event>.json` in the session directory (`approval_hook.sh event`: 10-digit monotonic seq under `events/seq.lock`, a symlink naming the holder's pid, taken over only when that pid is gone; published with `ln`, never overwriting a file, 0600, no output, exit 0 within ~2.5 s; readers take only `ev-*.json` and ignore `tmp.*`, `seq`, `seq.<pid>`, `seq.lock`). Install is idempotent: an equal entry stays, an older Atem entry is replaced in place, a missing one appended, extra Atem entries of an event dropped. The merge keeps every other byte, writes `hooks.json.atem-bak` first (empty when there was no file) and keeps the file's mode. Setting `[codex] hooks = false` removes every Atem-marked entry on the next `atem agent launch codex` (only groups made of marked hooks; anything unexpected is refused; a copy first as `hooks.json.atem-removed.<secs>`; read back and restored if it doesn't match; no file again when there was none before Atem and nothing else is left); `atem unpair` never touches hooks.json. A Codex hook counts only when the session's agent started it: directly (or through one shell) its Codex session becomes the pinned one, so `/new` keeps working; through a non-shell child it must be the pinned session; a request without a session id counts only when the hook's parent is the agent itself. The worker reports each request redacted (tool, the command's first line or the file path, Claude's own `permission_suggestions` as "always allow" rules); the broker opens it in `SessionHost` whoever holds the lease: `approval_request` goes to subscribed attachments with `control` (view-only ones get nothing), a chat-v1 card appears in their conversations, and (r8 hosts only; an r9 host sends sealed push hints instead, see r9) `push_approval{approval_id, atem_device_id, session_id, tool, summary, expires_at}` goes to the relay as `{"type":"relay",…}` over the verified link (best effort: the latest state per approval is kept while the link is down, at most 64 entries; `push_resolved{approval_id, reason}` when it stops being pending). An answer is a `kind:"approval"` submission (allow once / always allow with an offered `rule_id` / deny with an optional message) from any attachment with `control` (r8 §G, lease-free): no lease check, its `lease_epoch` optional and ignored, it never grants, takes over, renews or releases the lease (no `lease_changed`/`session_changed`, the holder's queued input isn't fenced), `acquire` beside or in it is `unsupported_version`, and the first admitted answer wins (it goes `executing` and closes the approval in the same step; later ones are `stale_target`). The card then shows the decision (`allowed`/`always_allowed`/`denied`) with `reason: answered_remote`; every final card carries the first close reason (r8 `approval.card_reason`). The decision goes to the worker (`approval_decision`); `approval_applied` `ok`/`unknown`/`not_delivered` finishes the receipt `completed`/`outcome_unknown`/`rejected`, and one the agent never confirms is `outcome_unknown` after 630 s. A decision within 5 s of the hook's timeout is `not_delivered` (the hook might give up before taking it). Closes: `answered_remote`, `answered_terminal` (Claude: the tool ran, or its transcript shows the refusal), `interrupted`, `timed_out` (a hook that ended within 5 s of its timeout, our decision untaken or none), `released`, `process_ended`; lease changes never close one. Every write and paste to a Codex session carries `release_approvals` (Codex hides its prompt while a hook waits, showing "Running hook"): the waiting hooks get "no decision" and close `released` (status stays waiting), and the input that released them is consumed, never written, since the user never saw Codex's dialog it brings back (a `y` must not approve it): the local frontend gets the notice "Codex's approval was handed to the terminal; answer its dialog", a remote `input` is acked `written` with "the approval was handed to the terminal; not written", a remote prompt or interrupt is `rejected`; input after it is consumed too while the released hooks still run (at most 500 ms); input with no hook waiting is written as before. An adopted worker is told the approvals the new broker knows (none), so it releases the rest, without `push_resolved`: a phone notification may linger until its `expires_at`, and a tap gets `stale_target` (shown as already answered). Same-user processes that can see `ATEM_APPROVAL_DIR` can forge request files: the result is a fake card, never an agent action (same-user attackers are out of scope). Never an allow without a decision from Astation; any failure is "no decision". Codex can't take a persistent rule (`updatedPermissions` fails closed), so its cards offer an **Atem session rule** instead (contract §6a r7.2): `always_rules` holds one `{rule_id: "s-<16 hex>", label: "Always allow `<command's first line, redacted>`[ (+N more lines)] in <cwd> for this session", scope: "session"}` only for a shell command (`Bash`/`shell`/`exec_command` whose `tool_input` is a string `command` plus at most `description`; any other key, e.g. a workdir or env, gets no rule) with the hook's session `cwd` (`approvals::RuleMatch`, built from the unredacted request and never leaving the worker); file changes (`apply_patch`) never get one (Allow once / Deny), though an `apply_patch` run as a shell heredoc is a command like any other (byte-exact, patch text included). An `allow_always` naming it is a plain allow for the hook; once the hook took it the worker keeps the rule for this agent process (`worker_approvals`: at most 32, a full session offers none, and one full by the time the hook takes the answer is reported `approval_rule_not_kept`, so the card ends `allowed` with a `note`; gone when the process ends, so a respawn starts with none; each kept with the `account_id`, `atem_device_id` and `host_trust_gen` it was granted under (`granted_under` on the `approval_decision`; a decision without one keeps nothing); kept across broker restarts but unconfirmed after every new broker connection, when matching requests ask as usual: the worker reports its rules as `approval_rules` (each `{rule, granted_under, confirmed}`) on connection and on `request_approval_rules`, which the broker sends when it registers a session, and the broker answers `confirm_approval_rules{rule_ids}` naming those granted under its current identity and trust — the worker confirms them and drops every other unconfirmed one; a new account, device or host trust generation while the broker runs sends every worker `revoke_all_approval_rules`). A later request of the session's pinned Codex (never a nested or foreign `codex`) whose tool, full command (byte-equal) and cwd equal a rule's is answered allow by the worker itself while a broker is connected: no approval, no push, no lease; the worker reports `approval_auto_allowed{rule_id, tool, summary}` (redacted), the broker writes one runtime.log line naming the session, tool and rule (never the command) and shows an `auto_allowed` chat card with `rule_id`. Anything else still asks (an extra `; rm`, another cwd, one byte more). The active rules go to attachments with `control` as session-v1 `approval_rules{session_id, process_gen, rules}` (on change, after each `sessions` snapshot, `[]` when the process ends) and to chat-v1 (`opened.approvalRules`, `rules` on change); any attachment with `control` revokes one, with or without the lease (r7.3), with a `kind:"approval_rule_revoke"` submission `{rule_id}` (chat-v1: `submit` with `approval_rule_revoke` instead of `text`; view-only is `forbidden`, an inactive rule or another process `stale_target`; `lease_epoch` optional and ignored, `acquire` refused; it never takes, renews or moves the lease; journaled with a receipt like any submission), dispatched to the worker (`revoke_approval_rule` → `approval_rule_revoked`, one runtime.log line naming the rule and session, never the command), completed when it dropped the rule; an allow written for that rule that the hook hasn't taken is withdrawn (Codex's own dialog asks). No local prefix-key revoke yet. Claude's rules are unchanged (its own suggestions, echoed as `updatedPermissions`). An interrupt whose Esc only handed a waiting Codex approval to Codex's dialog is `rejected` "the approval was handed to the terminal; interrupt again to stop the turn" (a prompt: "the approval was handed to the terminal; not written").

**Atem Memory** (`src/memory/`): `atem sync`, `atem memory …`, `atem skill …`. Agents learn from each other across agents and machines. Claude's saved memories are harvested (an edited file becomes a replacement, a deleted file an invalidation), Codex saves facts with `atem memory add --agent codex` and replaces outdated ones with `atem memory replace <id> "<new fact>"` (its block shows each fact's short id), and skills are versioned directories (`atem skill history`/`atem skill restore` read old versions from the relay). Facts are never edited in place: `memory replace`/`memory invalidate` keep the history (`valid_at`, `invalid_at`, `superseded_by`; see `memory list --history`), invalidation is final, and only valid facts are injected — a block that leaves facts out says how many and points to `atem memory search`, which is local FTS5 (trigram, BM25) over `knowledge.db`. Everything is synced through the relay (`/api/memory`, `/api/skills`, Astation pairing-session auth) with an offline SQLite store, then applied as a managed block in `~/.claude/CLAUDE.md`, `~/.codex/AGENTS.md`, and `<repo>/CLAUDE.local.md`, and as skills in `.claude/skills` and `.agents/skills`. Credential values are never stored: names only. Tracked files are never written. See `designs/atem-memory.md`.

**Cred agent** (`src/memory/cred_agent.rs`, `agent_socket.rs`, `unlock.rs`): this device's keys live sealed in `device_keys.sealed` under a storage key only the home Astation (the first one this device verified with) holds. The hidden `atem cred-agent` (same binary, started on demand, detached; Unix socket, same-UID peers only, `"v": 2` JSON lines; `PR_SET_DUMPABLE=0` on Linux, and `mlockall` there when `RLIMIT_MEMLOCK` is unlimited or ≥ 512 MiB; one agent per key directory via a `flock` on `cred/agent.lock`; an agent whose socket disappears, e.g. logind removing `$XDG_RUNTIME_DIR`, wipes its keys and exits within ~5 s) holds the unlocked keys; while it is locked, grants are ignored (`encryptionMode`/`keyGrant` arriving while atem waits for another reply are applied, not dropped, and after an unlock atem sends `keyRequest` if the signed state still needs `K`; an already unlocked `atem cred unlock` still connects while the signed state is `enabling`/`disabling`, to finish the migration and send the signed completion, since `atem sync` never talks to Astation). `atem cred unlock` asks it for a single-use key, sends an `unlockRequest` signed by `unlock_auth_key`, and hands Astation's Touch-ID-approved, signed `unlockGrant` straight back to the agent; the agent then rotates the storage key in three crash-safe phases (`.next` → `storageKeyAck` → promote, `.prev` kept until the next unlock → `storageKeyConfirm`), abandoning a stale pending key if needed. `atem pair` escrows the first storage key in the same run; until Astation is known to hold it, a fresh device keeps a plain `device_keys` file, which the agent re-seals at each start and deletes at the first confirmed escrow, so an agent that stops first loses nothing; `atem cred lock` wipes the agent and stops it (always allowed: the agent stops listening, removes its socket and `cred/agent.socket`, gives requests in flight up to 1 s, clears its pid from `cred/agent.lock` and exits; the CLI waits up to 2 s for it to go; one that hasn't stopped by then is reported as still running, and the next `atem cred unlock` replaces it). The key state is shown by `atem status` (see SSO auth). An `unlockDenied` with `revoked: true` (or "revoked" in its reason) is recorded in `cred/state.json` (`atem status` shows "revoked by <id>"; `atem pair verify` then refuses); `atem unpair` with the agent locked (or not running) renames the old key files to `<name>.revoked-<stamp>` and forgets that Astation's verification, home and escrow state, so the next `atem pair` verifies with new keys (the signal is unsigned: a forged one costs a re-pair, never keys or trust; verification itself never sets keys aside). `K` lives only in the agent: it installs granted keys into the sealed payload (`InstallGrant`; a payload with keys is `version: 2`), does every seal/open/keyed hash for `EncryptionContext` in batched `Crypt` requests (no reply carries `K`), takes the mode and kid from the newest signed account state across every verified Astation naming the account (one helper, `verification::effective_state`, for install, `Crypt`, `account_mode` and `key_needed`), and serializes key payloads into exactly sized wiped buffers; a locked agent keeps sync changes queued until `atem cred unlock`. A restart before the first escrow loses `K`, which is requested again. The status reply carries the agent's `build` (`cred_agent::build_id`: version + the executable's mtime and size when the agent started, so every rebuild differs). A command that may start the agent compares it with its own once: a locked agent of another build is asked to stop (one that doesn't is an error saying to run `atem cred lock`) and this build's agent is started; it holds no keys, so nothing is lost. An unlocked one is never restarted: the command warns once (`cred_agent::OLDER_BUILD`, "The cred agent was started by another atem build; run `atem cred lock`, then `atem cred unlock` to use this one."; `OLDER_RUNTIME` instead, pointing to `atem runtime restart` first, when a passive look finds Atem's runtime — which starts the agent for an unlock — of another build too) and uses it, a request it rejects as unknown gets that hint instead of the raw error, and `atem status` adds the same advice to its Credentials line (builds are compared for equality only: a dev build and the npm release of the same version differ, and neither counts as newer). The unlocked agent also signs what atem reports to Astation: `CredentialProjects` (the HPKE credential-project report plus optional original-case `labels`, `credential_projects.rs`; sent best effort after each authenticated connection, on `credentialProjectListRequest`, and by `atem cred projects`) and `MigrationComplete` (the `atem-migration-complete-v1` completion with its `K` possession proof, sent only after the read-back pass in `migration.rs` finds every protected field migrated). See `designs/e2e-encryption.md` "Keys on disk (atem)", and `docs/credential-project-reporting.md`.

**Webhook Server** (`webhook_server.rs`): Receives Agora webhook POSTs (ConvoAI events 101–111, 201–202; RTC NCS events) on a local HTTP port. each write raises `high_water` to at least the wall time and every retained entry's `until − 65 min`; the host's trusted time is `max(wall, high_water)`: a non-live revocation is kept until trusted time + 65 min and a new quarantine ends no earlier than `max(until, high_water + 65 min, trusted time + 65 min)`; browsers are refused `busy` "host clock went back" while the wall clock is below `max(until, high_water)`, with no override (wait for the clock; removing `runtime/journal/`, `runtime/` or the revoked grants' files is no way out, clock behind or not: `pairing/revoked_floor` keeps the bound). The files vouch for each other: `revoked_grants` missing or unreadable next to the sidecar or a `*.damaged-<ms>` copy, or the sidecar missing or unreadable (kept aside as `revoked_quarantine.damaged-<ms>`) next to `revoked_grants` or a copy, fails closed (`busy` "revoked grants unreadable"; a lost sidecar's bound rebuilt from the entries and record left, the journal directory's newest mtime as an extra floor). The bound also has a copy outside the journal, `pairing/revoked_floor` (same format, only ever raised, written durably before the sidecar at every write that raises it and at the pin; kept by `atem unpair`); it floors the bound, and a sidecar below it (the journal restored or rolled back) or an unreadable copy on a pinned host fails closed the same way. A pin seeds the copy and both journal files (a re-pin over an existing journal raises its sidecar to the copy, so it isn't read as a rollback), so on a host with a pinned device list none of the journal files (`runtime/` removed) is lost too: quarantined from `max(the copy, the list's clean checkpoint `at_wall`, the newest write in `pairing/` and in the journal) + 65 min` and trusted time + 65 min; only a host without a pinned list and none of them is fresh. What remains: removing both `pairing/` and `runtime/` (an unpair; pairing again needs Astation's ceremony), restoring both from an older backup, and same-user tampering (out of scope). A failed sidecar or file write answers `revoke_grant` `busy` "revocation not recorded" (still in effect in memory, the live browser fenced)); browser principals (`browser:<grant_id>`) leave `principals` once no attachment, lease or unfinished request names them | None (dir 0700, files 0600, replaced atomically; ids, codes and outcome words only, no prompt payloads after a request leaves `accepted`) |

**Identity** (`config.rs`, `websocket_client.rs`):
- `instance_id` — persistent UUID v4, the canonical atem identity (and the vault `client_id`). Generated once by `ensure_instance_id()`, stored in `config.toml`.
- `atem_id` — the relay-room id `<host>[-<filler>]-<suffix:8>` (host + filler = 12 chars; e.g. `Genie-dc1649f-956631ec`), generated once (`build_atem_id`) and frozen in `config.toml` so it survives restarts and hostname changes. Keeps non-ASCII hostnames (Chinese/Japanese/Korean), restricts ASCII to `[A-Za-z0-9-]`, percent-encoded into the relay URL. See `designs/atem-identity.md`.

**Logins and the pairing** (`credentials.rs`, `pairing.rs`, `paths.rs`): one pairing at a time. A `Login` keeps identity and Agora connection apart (`issuer` + `subject` + identity `tokens`; `connections.agora` for a future non-Agora issuer); `Login::agora_tokens` is the only way to Agora API tokens (an issuer that isn't Agora SSO without an Agora connection: `credentials::NO_AGORA_CONNECTION`). Agora SSO is an exact allowlist: `sso2.agora.io` (`AGORA_SSO_ISSUER`, also the issuer of every login Astation shares) and the host of the configured `sso_url`. `valid_token` chooses, in order: the pairing's shared login while the link to that Astation is up (`shared_while_connected`); the user's own `login.enc`; the shared login when kept for offline use (`save_credentials`) or within 5 min of `disconnected_at` (`shared_offline`; stamped when the link drops, cleared by the next `credentialSync`). Writes to `pairing.enc` hold `trust_gen.lock`: inside `Captured::apply` through `PairingRecord::update_locked`, elsewhere through `PairingRecord::update`, which also refuses when the binding the caller read changed (so a write never brings back a pairing removed meanwhile).

**SSO auth** (`sso_auth.rs`):
- `atem login` — OAuth 2.0 + PKCE browser flow against `sso2.agora.io`; writes `login.enc` (issuer from `sso_url`)
- `atem logout` — removes `login.enc`, then tells a running runtime to `reload`
- `atem status` (tier 0, `src/status.rs`; the only status command) — read-only: `Account` (signed in / signed in (expired) from `login.enc`, else signed in through Astation [(expired)] from the pairing's shared login, else signed out), `Pairing` (`paired (<astation id>, trust gen N)`; `, session expired` when its saved session expired; `not paired (unfinished pairing with <id>; run `atem pair`)` for a record without a current binding, which `atem pair` and `atem pair verify` treat as not paired (`atem pair` replaces it; only `atem pair` creates a record: background connections and re-authentication only update the bound pairing's session, else keep a granted session in memory); `unknown (<error>)` for an unreadable record; or `not paired`), `Verification` (`verified (safety code …)` / `not verified` / `revoked by <id>` only when that is the paired Astation / `—`), `Credentials` (`unlocked` / `locked` / `not set up` / `broken (<problem>)` with `cred_agent::RESET` printed after the block; plus `(storage key not yet held by Astation; run atem cred unlock)` for an unlocked, unescrowed agent and `(started by another atem build; run atem cred lock, then atem cred unlock)` for another build's agent; asks only an already running cred agent, never starts one; no agent = locked), and from an already running runtime (a passive `status` within 500 ms): `Authorization` (`authorized (r8, since HH:MM, N h left)` / `not authorized (Astation not connected | Astation connected but no session hello yet | the Astation link isn't a verified pairing …)` / `refused (Astation sent revision 7; needs r8)` from the last refused `hello` / `paused (journal halted; run atem runtime restart)` / `unavailable (<host error>)`), `Relay` (`connected via relay (<relay host> as <atem_id>)` / `connected locally` / `not connected (retrying)`), `Local agents` (`2 running (claude ready, codex working); 1 exited`); all three `no runtime running` without one. Never starts anything, never writes, never uses the network. "Paired" = a pairing record exists. A paired profile whose session expired or was refused gets `The saved Astation session expired or was refused. Run `atem unpair`, then `atem pair`.` instead of "run `atem pair`" (pairing gate, memory sync/history, TUI re-authentication, connect errors, `pair verify`)
- `atem pair [--save]` — on an already paired profile (even unverified or revoked) prints the status plus `Already paired. Verify this device: atem pair verify · Replace the pairing: atem unpair, then atem pair` and exits 0 without connecting or changing anything. Otherwise, inside `atem runtime` on its link: send `PairSavePreference`, wait for `CredentialSync`, bind the pairing (`pairing::bind_new`) and store the shared login and the save choice in it, then verify the device: commit-then-reveal (`verifyCommit` → `verifyKeys` → `verifyReveal`), both sides show a 12-character safety code, the user answers `codes match? [y/N]` (read from `/dev/tty`, flushed first, never stdin; no terminal fails the verification) and confirms on Astation with Touch ID, and atem applies the signed `deviceVerified` atomically (pins, device keys, signed state, grants; nothing on failure). If `K` is needed but missing it sends `keyRequest`. Astations that don't answer within 15s leave the device as it was (see `designs/e2e-encryption.md`). Any later failure (code refused, no terminal, 300 s Touch ID timeout, lost connection, apply error) drops the pending pin and sends `verifyAbort` with delivery confirmed (not when Astation itself aborted); the pairing stays saved and `atem pair` exits nonzero (`atem pair verify` retries). A failed `keyRequest` after success is only a warning (`atem cred unlock` asks again). Logic and tests: `src/pair_verify.rs`. On the home Astation's first verification the fresh keys are sealed and the first storage key is escrowed (`storageKeyRotate` with an empty old kid, then confirmed) in the same run
- `atem pair verify` — needs a pairing (`Not paired. Run atem pair first.`, exit 1); already verified with the paired Astation → `Already verified (safety code …).`, no connection; revoked → `This device was revoked by Astation <id>. Run atem unpair, then atem pair, to set it up again.`, exit 1, nothing moved. Otherwise runs the same verification as `atem pair` (`run_device_verification`) inside `atem runtime`, on its link authenticated with the saved session (never pairing; see "Astation operations through the runtime"). A cancelled or failed verification keeps the pairing
- `atem cred projects|unlock|lock` (tier 2; the key state is shown by `atem status`) — send the current Git project and the account's remembered project names to the home Astation's credential picker (keys must be unlocked; runs in `atem runtime`, waiting up to 15 s for its link; see `docs/credential-project-reporting.md`); Touch ID unlock through the home Astation, also in the runtime (waits up to 300 s, then rotates the storage key; when already unlocked it still finishes a pending migration; an unverified device stops offline with `This device isn't verified. Run atem pair verify first.`, and it never starts pairing or verification); wipe the unlocked keys and stop the agent. `atem cred-agent` is the hidden agent process itself
- Host trust generation (`pairing.rs`): asynchronous Astation work (connect and re-authentication, `atem pair`/`pair verify`, `atem cred unlock` rotation/escrow, credential-project reports, `credentialSync`, `encryptionMode`/`keyGrant`) captures the trust generation and binding, and the saved session its proof used, when it starts (`AstationClient::capture`), and applies a reply only while both are unchanged, under `trust_gen.lock` (`Captured::apply`; a binding of an older generation than `trust_gen` is no binding; cred-agent requests through `BoundAgent`). A reply that arrives after `atem unpair` or a new `atem pair` is dropped (`pairing::CHANGED`): no session refresh, no credentials, pins, grants or storage-key promotion. Encryption messages on a connection without a binding yet are held. `atem status` shows `paired (<id>, trust gen N)`
- `atem unpair [--yes]` — first commits the next host trust generation (`pairing/trust_gen`), then removes `pairing/pairing.enc` (`pairing::unpair`; the user's own login, memory, vault data, trust pins and keys stay), and set revoked keys aside (see Cred agent); a failure to set them aside, or a revocation left recorded (agent unlocked, or not the home Astation), is printed as a notice and the unpair still completes. It, `atem memory purge` and `atem skill purge` confirm first (`cli::confirm_destructive`): `--yes` skips the question, and without a terminal they refuse unless `--yes` is given. The purge prompts show the id and scope only, never the content, since a purged item may hold a credential. Unpair then tells a running runtime to `reload`, which drops the link of the removed pairing and its attachments
- `valid_token(connected_astation_id, sso_url)` — the Agora access token of the login chosen as above. Within 60 s of expiry the own login refreshes at `sso_url`; a shared one never does (Agora rotates refresh tokens, so it would invalidate Astation's copy): the runtime's `token` operation waits for Astation's next `credentialSync`.

**BFF API** (`agora_api.rs`):
- `fetch_projects(access_token, bff_url)` — `GET {bff_url}/api/cli/v1/projects`, Bearer auth, returns `Vec<BffProject>`

**WebSocket messages** (`websocket_client.rs`):
- `CredentialSync { access_token, refresh_token, expires_at, login_id, astation_id, save_credentials }` — Astation → Atem, after pair, on connect, or on Astation-side refresh (replaced `SsoTokenSync`)
- `PairSavePreference { save_credentials }` — Atem → Astation during `atem pair`, communicates user's save choice
- `VerifyCommit { device_id, commitment }` — Atem → Astation, starts device verification with a commitment to unrevealed keys
- `VerifyKeys { sign_pub, enc_pub, recovery_sign_pub, nonce }` — Astation → Atem; `sign_pub` is the 65-byte uncompressed P-256 point
- `VerifyReveal { device_pub, device_sign_pub, unlock_auth_pub, nonce }` — Atem → Astation, the keys and nonce behind the commitment
- `DeviceVerified { device_verified, account_state, grants }` — Astation → Atem after Touch ID: signed certificate (bound to the ceremony transcript), signed account state, signed HPKE grants
- `VerifyAbort { reason }` — either side cancels verification
- `EncryptionMode { account_state }` — Astation → Atem, a signed `atem-account-state-v1`; ignored when unsigned or when the device isn't verified
- `KeyRequest { public_key }` — Atem → Astation, a verified device asks for `K`
- `KeyGrant { grant }` — Astation → Atem, `K` sealed to this device with a signed grant; ignored when unsigned or unverified
- `UnlockRequest { request, signature }` — Atem → home Astation, `atem-unlock-request-v1` signed by the unlock-auth key
- `UnlockGrant { grant, encapped_key, ciphertext }` / `UnlockDenied { reason, revoked }` — Astation → Atem, the storage key sealed to the request's single-use key, or a denial
- `StorageKeyRotate { rotate, encapped_key, ciphertext }` — Atem → home Astation, a new storage key sealed to Astation's encryption key, device-signed
- `StorageKeyAck { ack }` / `StorageKeyRejected { reason, pending_kid? }` — Astation → Atem, stored as pending, or refused (`pending_kid`: Astation is committed to that pending key)
- `StorageKeyConfirm { confirm }` / `StorageKeyAbandon { abandon }` — Atem → home Astation, device-signed: switched to the new key / give up a pending key this device has no file for
- `EncryptionMigrationComplete { mode, kid, completion }` — Atem → Astation after a migration's read-back pass (`mode` `on`/`off`): `completion` is a device-signed `atem-migration-complete-v1` with a `K` possession proof, made by the agent (`MigrationComplete`); sent flushed so a short-lived CLI can exit
- `CredentialProjectListRequest` — Astation → Atem, asks an unlocked device for its credential-project report
- `CredentialProjectListResponse { report }` — Atem → Astation, after every authenticated connection, on request, and from `atem cred projects`; `report` is `{signed, encapped_key, ciphertext, labels?}` (HPKE to the pinned Astation key, device-signed by the agent's `CredentialProjects`; `labels` carries original-case spellings). Locked or unverified devices send nothing

### Capability Tiers

Product rule: `atem login` unlocks a limited set of functions (tier 1); pairing
with Astation unlocks the full set (tier 2) — Astation is the control plane.

| Tier | Needs | Commands |
|---|---|---|
| 0 | — | status, serv files, config, token with AGORA_APP_ID/CERT env, `project use <index>`, `project show` (local cache) |
| 1 | `atem login` | `project list`, `project use <app-id>`, token (active project), serv rtc/convo/webhooks |
| 2 | paired with Astation (verified, for remote sessions) | vault, sync, memory, skill, cred, and Astation-driven terminal viewing and control, chat and mark tasks |

Gates are centralized in `src/auth.rs`: `require_login(feature)` is the tier-1
gate (passes with `login.enc` or a login the pairing shares);
`require_pairing(feature)` is the tier-2 gate (resolves a `PairedSession` —
relay base, Astation id, session id — from `AtemConfig` + the pairing
record, purely local, no network). Both return an actionable `anyhow::Error` built
from `login_gate_message`/`pairing_gate_message` when the check fails.

New cross-machine or cross-agent features are tier 2 and must gate with
`auth::require_pairing`.

## Release Process

**Use `./scripts/release.sh`** — it keeps `Cargo.toml` in sync with the git tag and
guards against common mistakes (dirty tree, duplicate tag, failed build).

```bash
# Patch-bump (reads current Cargo.toml version, adds 1 to the last segment)
./scripts/release.sh

# Or explicit version
./scripts/release.sh 0.5.0
```

What the script does:
1. Resolves target version (auto patch-bump, or from argument)
2. Refuses if tag exists or working tree is dirty (except Cargo.toml/Cargo.lock)
3. Updates `Cargo.toml` → bumps version
4. Runs `cargo build` to refresh `Cargo.lock`
5. Creates a commit for `Cargo.toml` + `Cargo.lock`
6. Creates the tag `vX.Y.Z` locally
7. **Does NOT push** — prints the push command so you can review first

To publish after running the script:
```bash
git show HEAD               # review the release commit
git push && git push origin vX.Y.Z
```

Pushing the tag triggers GitHub Actions (`.github/workflows/release.yml`):
1. Builds binaries for linux-x64, linux-arm64, darwin-x64, darwin-arm64
2. Creates GitHub release with tarballed binaries
3. Publishes `@agora-build/atem` to npm (version synced from tag)

The same workflow builds the atem-core macOS package (`scripts/package-atem-core-macos.sh`) and attaches three assets to the release: `atem-core-<version>-macos-xcframework.zip`, `atem-core-<version>-atem_core.h` and `atem-core-<version>-SHA256SUMS.txt`. See `crates/atem-core-ffi/README.md`.

Requires `NPM_TOKEN` secret in GitHub repo settings.

**Don't manually bump `Cargo.toml` + `git tag` separately** — the two can drift
(any `atem --version` will show the stale Cargo.toml number even if the tag is newer).

## Integration Points

- **Astation**: macOS menubar hub that coordinates Chisel, Atem, and AI agents — talk to your coding agent from anywhere (WebSocket)
- **Chisel**: Dev panel for visual annotation and UI editing by anyone, including AI agents (`.chisel/tasks/`)
- **Claude Code CLI**: Spawned as PTY subprocess for AI-powered code implementation
- **Agora REST API**: Project management, credential fetching
- **Conversational AI (`atem serv convo`)**: Launches a local HTTPS test page that
  drives Agora ConvoAI v2 (`/join`, `/leave`). Config loaded from
  `~/.config/atem/convo.toml` (override via `--config`). Page uses the vendored
  Conversational-AI-Demo toolkit at `assets/convo/` (refreshed by
  `scripts/update-convoai-toolkit.sh`, reproducible from a committed lockfile and pinned esbuild, stale bundles blocked at release time).
  Features: live transcription (RTM), preset checkboxes, avatar video
  (Akool/LiveAvatar/Anam), RTC Stats, API History, camera toggle,
  RTC encryption (key + base64 salt sent to ConvoAI as `properties.rtc.{encryption_key, encryption_salt, encryption_mode}`;
  same params applied to local Web SDK so both peers decrypt). gcm2
  modes (7, 8) require a 32-byte salt; the page auto-generates one and
  exposes it as a copyable, editable field. Project must have Media
  Stream Encryption enabled in the Agora console for the appid.

  `--background` re-execs as a detached daemon (mirrors the rtc daemon
  pattern): parent POSTs `/join`, registers `{id, pid, kind="convo",
  channel}` in `~/.config/atem/servers/<channel>.json`, exits. The
  daemon catches SIGINT + SIGTERM (so `atem serv kill` works) and
  POSTs `/leave` before exiting. A tokio task on the daemon polls
  `GET /agents/{id}` every `[atem].poll_interval_secs` (default 60,
  floored to 5) and writes `last_status` + `last_checked_at` into
  the registry JSON — `atem serv list` reads the cached value with
  no network round-trip. The daemon log (`<channel>.log`) contains
  the `/join` URL (HIPAA path when applicable) and the request body
  with secrets masked (api keys, tokens, encryption_key, certs).

  `--channel` supports `{appid}` (first 12 chars of active app id) and
  `{ts}` (unix epoch seconds) placeholders, expanded by atem at startup.
  Lets fleet for-loops produce channels matching the default auto-gen
  shape without computing prefix/timestamp in the shell:
  `atem serv convo --background --channel 'atem-convo-{appid}-{ts}-001'`.

  `convo.toml` schema:
  - `[atem]` — atem's runtime control surface. atem reads each field
    and decides how to dispatch (URL prefix, build the avatar block,
    pre-fill the web form, etc.). Fields:
    - `channel` (RTC channel name; auto-generated when omitted)
    - `rtc_user_id` (human's RTC uid; "0" = server-assigned)
    - `pipeline` — `"cascaded"` | `"mllm"`. Picks which provider
      block goes into `/join` when both are parked in the file.
      Auto-detected from which block is present when omitted; required
      when both `[agent.asr/llm/tts]` and `[agent.mllm]` exist.
    - `env` — ConvoAI REST environment: `ga` (default, api.agora.io/api) |
      `eap` (partner.ai.agora.io/preview/api + `agora-feature: live-models`
      header; Early Access Preview) | `hipaa` (api.agora.io/hipaa/api, forces
      NORTH_AMERICA + AES_256_GCM2). `[atem].hipaa = true` is a legacy alias
      for `env = "hipaa"`. The web UI shows the environments as single-select
      radios with a live endpoint-URL preview.
    - `[[atem.environments]]` — add/override environments (`name`, `host`,
      `prefix`, `label`, `headers`, `force_geofence`, `force_encryption_mode`).
      Merged over the built-in ga/eap/hipaa by `name`; a new name adds a
      selectable environment — no code change. `ATEM_CONVOAI_API_URL` overrides
      the ga/hipaa host.
    - `envs` — allowlist of environment names to show in the UI, in order
      (e.g. `["ga", "eap"]` hides HIPAA). Empty/omitted → show all. The
      selected `env`/`hipaa` default is clamped to a shown entry.
    - `geofence` — GLOBAL | NORTH_AMERICA | EUROPE | ASIA | JAPAN | INDIA
    - `enable_avatar` — opt in to `[agent.avatar]` this session
    - `[atem.encryption]` — `mode` (0..=8), `key`, `salt` (base64-32-bytes)
  - `[agent]` — about the AI agent itself:
    - `user_id` (the agent's RTC uid; required)
    - `idle_timeout_secs` (server-side reaper)
    - `preset` (comma-separated string; UI splits to checkboxes,
      joins selections back as `properties.preset`)
    - `[agent.llm]` / `[agent.asr]` / `[agent.tts]` / `[agent.avatar]`
      — cascaded provider blocks, forwarded under `properties.<svc>`.
      `[agent.llm]` also accepts `[[agent.llm.mcp_servers]]` entries
      ({`name`, `endpoint`, `transport`, `headers`, `allowed_tools`,
      `timeout_ms`}) → `properties.llm.mcp_servers[]`. When any MCP
      server is present atem auto-sets `advanced_features.enable_tools
      = true` unless that field is pinned in `[advanced_features]`.
    - `[agent.mllm]` — single multimodal model that replaces
      asr+llm+tts. Per Agora's MLLM schema: `vendor`, `url`,
      `api_key`, `greeting_message` at the top of the block; vendor
      knobs (`model`, `voice`, `instructions`, …) under `[…params]`.
      atem auto-injects `enable: true`, `input_modalities: ["audio"]`,
      and `output_modalities: ["text", "audio"]` so the agent emits
      audio. MCP works here too: `[[agent.mllm.mcp_servers]]` (same
      shape as the LLM's) → `properties.mllm.mcp_servers[]`, and
      `enable_tools` is auto-set the same way.
  - Pass-through tables — `[advanced_features]`, `[vad]`, `[sal]`,
    `[parameters]` — atem forwards verbatim as `properties.<key>`.

  Implemented as `ConvoConfig { atem: Option<AtemSection>, agent:
  Option<AgentConfig>, …pass-through… }`. `[atem]` values flow into
  both the web UI (form pre-fills via `DEFAULT_*` JS constants
  emitted by `build_html_page`) and `--background` mode (sent to
  ConvoAI's `/join` body via the resolved values on `JoinArgs`).
  `atem config convo --validate` checks the schema (geofence value,
  encryption mode/key/salt consistency, etc.) — see
  `convo_wizard::run_validate`.

- **`atem serv attach <id>` / `atem serv attach <#>`**: Opens a foreground
  HTTPS UI bound to a running convo daemon's channel. Looks up the entry
  in the servers registry, validates `kind == "convo"`, spawns the
  convo HTTPS server with `attach: true`. The page receives `ATTACH_MODE
  = true` which hides the Start/Stop buttons (the daemon owns the agent;
  trying to /start would create a duplicate agent on the same channel).
  User joins the channel with their RTC uid + matching encryption to
  talk to the live daemon-owned agent.

- **`atem serv list/kill/killall` registry conventions**: All servers
  (rtc, convo, webhooks, files) write JSON entries to `~/.config/atem/servers/`.
  Convo entries use the channel name itself as the id (no kind/port
  suffix) since channels are unique per agent. `list` shows a 1-based
  index (`#`), `ID`, `PID`, `PORT`, `STATUS` (cached from convo's 60s
  poller, `—` until the first poll). `kill` and `attach` accept either
  the literal id or the index from `list`.
- **ConvoAI Config Wizard (`atem config convo`)**: Interactive terminal wizard
  that generates `~/.config/atem/convo.toml`. Flow: Channel & User → Agent →
  Preset (empty = skip) → Add Custom override? → Pipeline (Cascaded | MLLM)
  → Avatar. Preset and Custom stack — preset sets defaults, explicit blocks
  override per-field. Pipeline pick is single-select; the parked one stays in
  the file (`[atem].pipeline` switches between them at runtime). Provider
  selection: ASR (10 vendors), LLM (9), TTS (12), MLLM (4 — OpenAI Realtime
  default `gpt-realtime`, Gemini Live, Vertex AI Gemini Live, xAI Grok),
  Avatar (3). MLLM `api_key`/`url`/`greeting_message` written at the top of
  `[agent.mllm]`; `instructions`/`model`/`voice` go in `[agent.mllm.params]`.
  Pre-fills from existing TOML on re-run; `.bak` rotation keeps last 5
  generations. `--validate` performs read-only schema checks (required
  fields, large-integer precision issues, vendor completeness).
