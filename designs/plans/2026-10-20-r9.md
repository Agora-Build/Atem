# atem-session r9 Implementation Plan (remote clients)

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Implement the r9 contract signed off by Astation at `c685aba` (merged as `685e213`): the Atem-owned shared client core `atem-client` (Rust, with Swift/Kotlin/WASM bindings) and the Atem host side, so phones, bots and browsers reach Atem directly, independent of the Mac, and every `r9-*` shared fixture passes.

**Architecture:** A new workspace crate `crates/atem-client` holds everything security-critical that both sides need: canonical encoding and signing (§R9.2), the membership-log verifier (§R9.2–§R9.5), the `atem-ch1` channel in both roles (§R9.7), recovery/K-backup formats (§R9.5), push-hint and `seen` formats (§R9.9), the r9 client machines and the fixture runner. It is sans-I/O; keys go through a `KeyProvider` trait. The Atem host links the same crate for verification and the channel responder, and adds durable membership state (carriage record, head, freeze, held, pending recovery), r9 admission of principals, and sealed push.

**Spec:** `designs/protocol/atem-session-v1.md` — Appendix r9 (§R9.1–§R9.13) is binding; `designs/protocol/remote-agent-api-atem.md` (r3); `designs/account-trust.md`; fixtures `designs/protocol/fixtures/r9-*` and `schema.md`; Astation sign-off review r5 (https://github.com/Agora-Build/Astation/blob/10b2143/designs/protocol/remote-agent-api-atem-r5-review.md).

## Global Constraints

- Branch `feat/r9` from main `685e213`. Commits end with a blank line and `🤖 Built with SMT <smt@agora.build>`. Never push without the controller.
- The contract text and the shared fixtures are the authority. A fixture that contradicts the appendix: stop and report (shared with Astation).
- No backward compatibility (r9 replaces r8 for remote clients; the Mac uses the same channel).
- Crypto only from existing, reviewed dependencies (check `Cargo.toml`); no hand-rolled primitives; constant-time comparisons; zeroize secrets.
- Never rustfmt `src/app.rs`, `src/main.rs`, `src/cli.rs`, `src/websocket_client.rs`, `src/memory/{mod,crypto,secrets}.rs`; no project-wide `cargo fmt`.
- Tests never touch the real profile, `~/.claude`, `~/.codex`, the user's runtime, workers, cred agent or tmux `atem-jt`. Build with `CARGO_TARGET_DIR=/tmp/atem-target-r9impl`.
- Every task: its fixtures and vectors pass; full `cargo test` twice reading every result line; `cargo test --release` once; clippy not above main; CI (Linux, macOS arm64, macOS Intel) green before merge.
- **Local end-to-end tests (user, 2026-10-20):** besides unit tests and the shared fixtures, every task adds tests that exercise its functions the way they are really used on this machine: real processes (`atem runtime`, workers, fake Claude/Codex agents) and simulated remote clients (a phone, a bot and a browser driven through `atem-client` on a temp profile), real sockets, real files, fault injection. Each task's report lists these tests and what they prove. A function without such a test is not done.
- Status for Astation goes to Atem memory first (project Atem), then #81 when it needs links.

### Task 1: `atem-client` crate, encoding and signing
Workspace crate, `KeyProvider` trait (P-256 and Ed25519 signing, X25519, HPKE open), canonical encoding and domain-separated signing inputs (§R9.2), `alg` pinning, set-vs-sequence validation. A vector runner that executes every `r9-vectors-*` file. All vector files pass.

### Task 2: Membership-log verifier
Entries (add/remove/set_roles/recovery_add/approve/veto/set_recovery_key/k_backup), genesis and kit anchor (`kit_tag`, `genesis_hash`), chain verification, conflict classification (ignored vs freeze), recovery pending/approve/veto timing as a pure function of host-clock inputs, backup version allocation. Fixture runner support for chain/recovery/backup scenarios; those fixtures pass.

### Task 3: `atem-ch1` channel
SIGMA-I in both roles (initiator/responder), transcript, key schedule, framing, counters, limits, errors (§R9.7). Channel vectors and handshake fixtures pass (success, wrong head, tampered transcript, replay, zero-DH).

### Task 4: r9 client machines and push/seen formats
r9 hello/welcome inside the channel (identity proof, suffix carriage, `welcome.head`, `pending_recovery`), principals/scope/expiry checks, push hint sign/seal/verify and `seen`/`push_ack` (§R9.9). Client-side fixtures pass.

### Task 5: Bindings
UniFFI (Swift, Kotlin) and WASM builds of `atem-client`; a binding conformance test that runs the vector files through Swift (macOS CI) and the WASM build; CI jobs. Binding/effect contract doc for Astation.

### Task 6: Host membership state
Durable carriage record (written before evaluation, replayed at start), head, freeze, held (only after a recorded fault, user option 2), pending recovery on the host clock, clean checkpoint tied to `runtime_epoch`, fail-closed live fences through r8 §H on any fault. Host persistence fixtures pass, including fault injection (test-only hooks).

### Task 7: Host admission and channel responder
The runtime accepts r9 connections over the relay and LAN, runs the responder, admits principals (native/service/browser/host) with scopes and expiry, applies carried suffixes before admission, exposes pending recovery in `welcome`, `atem status` and the status row. Multi-attachment scenarios (Mac + phone, Mac off, takeover, approval while another holds the lease).

### Task 8: Sealed push and seen on the host
Signed `created_at`/`expires_at` hints, HPKE-sealed tool/summary per control device, resolution, `seen` handling and `push_ack` resend. Push fixtures pass.

### Task 9: Real-runtime fixtures, harness, docs, handoff
Every expressible `r9-*` fixture against the real runtime; the headless multi-device harness for Astation; AGENTS.md, READMEs, protocol status (r9 implemented), and the implementation/artifact pin + binding contract for Astation.
