# atem-session r8 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development.

**Goal:** Implement the r8 contract signed off by Astation at f9fa57a (merged as bc08c42) so every `r8-*` shared fixture passes in the core harness and, where the runtime can express it, against the real runtime.

**Architecture:** r8 replaces r7.3 outright (no backward compatibility). The host (`src/session_protocol/`) gains revision admission, principals with durable control generations, the persistence/recovery rules and the new chat history/receipt shapes; the runtime (`src/runtime/host_bridge.rs`, `broker.rs`, worker chat) carries them to the workers and agents; the fixture runners stop skipping `requires: "r8"`.

**Spec:** `designs/protocol/atem-session-v1.md` — the r8 appendix (§A–§I) is binding; `designs/protocol/agent-control-api-atem.md` (response r2–r5); `designs/protocol/fixtures/` (`r8-*`, `schema.md`); Astation reviews r1–r5 and the handoff `chat-send-control.md` (copies: /tmp/acapi-*.md, /tmp/chat-send-control.md).

### Task 1: Revision admission and features
`hello.revision` (8) required, `unsupported_version` + no attachment otherwise; `welcome.revision`/`features`; removed forms refused; `invalid_request` code; client-side checks in `session_protocol/client.rs`. Fixtures: r8 admission/client revision/features/open-before.

### Task 2: Principals, control generations and the journal (§H, §I)
Accepted work records principal + `control_gen`; durable revocation fence; refusal list; journal halt semantics; `clean_close` tied to `runtime_epoch`; restart resolution (acceptance not confirmed / authorization history unknown / host trust changed / control revoked / control not confirmed) and the 60 s confirmation after clean close; raw terminal writes blocked after a halt. FileJournal fault hooks for the fixture steps (`fail_next_fsync` + `undo_fails`, `fail_fsync_of`, `crash_after_accepted`, `crash_runtime`, orderly `restart_runtime`, `journal_halted`). Fixtures: §H/§I scenarios.

### Task 3: Lease-free approvals and chat Send acquire (§F, §G)
Approval answers need `control` only (lease untouched, `acquire` refused, first wins); prompt/chat `text` submit with `acquire`/`takeover`/`expected_controller`, atomic with durable acceptance; `lease_held` carries `controller`; digest excludes admission parameters. Fixtures: r8 send/approval scenarios.

### Task 4: Receipt result (§C)
Completed prompt receipts carry `result{turn_id, user_message_id, outcome, reply_message_ids ≤32, more}`; ids/outcome journaled, reply ids projected from retained history. Fixture: reply-ids bound.

Remove #75's `open.before`/`status.page`. Fixtures: r8 history scenarios.
